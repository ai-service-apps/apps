## Установлено и проверено (серверными запросами, без реальных платежей)

- Авторизация API AnyPay: `ok=true`, `api_authenticated=true`.
- Список платежей проекта: `payments_list_accessible=true`, `records_shape=empty` (на момент проверки реальных транзакций нет).
- Маршрут `/api/catalog`: HTTP 200, `ok=true`.
- Маршрут `POST /api/checkout`: HTTP 409, `CHECKOUT_NOT_ENABLED`.
- Маршрут `POST /api/anypay` с неверной подписью: HTTP 401, `INVALID_SIGNATURE`.
- Сверка подписи AnyPay и строгая привязка к номеру, сумме, валюте и неоплаченному серверному заказу присутствуют в обработчике `ap`.

- SQL-тесты: закрытый шлюз зачисления, отсутствие согласованных для распространения приложений и уникальность отпечатка уведомления. Тестовые записи откатываются.
- После тестов: 0 заказов, 0 событий оплаты, 0 зачисленных оплат, 0 разрешённых приложений.
- Временное расширение PostgreSQL `http`, использованное для диагностики, удалено.

## Реальные платежи НЕ разрешены

Обе настройки `web_app_payment_controls.checkout_enabled` и `real_payments_enabled` зафиксированы `false` на уровне CHECK-ограничений PostgreSQL.
`web_app_payment_events.confirmed_with_provider` также заблокирован в `false`.
Обработчик `ap` не меняет статус заказа на оплаченный, а функция кредитования заблокирована.
Кнопка «Оплатить» на публичном сайте отключена.

Никогда не включайте публичную оплату одним изменением кнопки или удалением CHECK-ограничений.

## Что потребуется до реального запуска

1. Документированное право распространять каждое предлагаемое приложение, включая способ подписи, передачи и активации. Совместное использование Apple Account не должно требовать передачи чужих секретов/2FA.
2. Подтверждение AnyPay, что категория услуги разрешена для приёма платежей.
3. Успешная проверка **настоящей** транзакции провайдера с полями транзакции (документированный формат API, транзакция именно проекта 18580). Текущее `records_shape=empty` не доказывает формат реального платежа.
4. Отдельный испытанный атомарный сценарий зачисления: уникальная транзакция, неизменная сумма из каталога, статус `paid`, защита от повторов и возвратов. Только после этого можно пересмотреть три защитных ограничения.
5. Юридические страницы и пользовательское соглашение должны соответствовать реальному оказанию услуги и требованиям платёжного провайдера.
