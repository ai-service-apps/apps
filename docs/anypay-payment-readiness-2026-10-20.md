## Что потребуется до реального запуска

1. Документированное право распространять каждое предлагаемое приложение, включая способ подписи, передачи и активации. Совместное использование Apple Account не должно требовать передачи чужих секретов/2FA.
2. Подтверждение AnyPay, что категория услуги разрешена для приёма платежей.
3. Успешная проверка **настоящей** транзакции провайдера с полями транзакции (документированный формат API, транзакция именно проекта 18580). Текущее `records_shape=empty` не доказывает формат реального платежа.
4. Отдельный испытанный атомарный сценарий зачисления: уникальная транзакция, неизменная сумма из каталога, статус `paid`, защита от повторов и возвратов. Только после этого можно пересмотреть три защитных ограничения.
5. Юридические страницы и пользовательское соглашение должны соответствовать реальному оказанию услуги и требованиям платёжного провайдера.

## Контрольная подпись SCI: исправление метода получения счёта

При открытии тестовой ссылки SCI вида `https://anypay.io/merchant?...` AnyPay возвращал «Неверная контрольная подпись» даже после выравнивания формата суммы; подтверждения рабочего SCI-секрета не получено. Поэтому закрытый пилот переключён с локально подписанного SCI-перехода на официальный эндпоинт `GET /api/create-payment/{API_ID}`, доступный с ранее проверенными `ANYPAY_API_ID` и `ANYPAY_API_KEY`.

- Сервер подписывает API-запрос SHA256 по `create-payment + apiId + projectId + payId + amount + currency + desc + method + apiKey`. Email передаётся провайдеру отдельно и не включён в контрольную сумму API-запроса.
- Создание счёта по нажатию на кнопку требует email для AnyPay, способ оплаты pilot установлен `card`.
- Для тестового заказа номер заказа и сумма 500 ₽ загружаются из Supabase, а не из клиентского запроса.
- Одна ссылка провайдера на контрольный заказ: защищённая таблица `web_app_pilot_invoices`, 90-секундная блокировка конкурентных попыток, на случай успеха кэширование URL.
- Возврат только доверенного URL `https://anypay.io/... ` без произвольных доменов.
- На 20.10.2026 публичная страница `/pilot.html` ответила HTTP 200, новое поле email и отправка значения в API подтверждены. Вызов с поддельным личным токеном получил HTTP 403 `INVALID_INVITATION`.
- До следующего действия владельца: 1 контрольный заказ, 0 выданных провайдером счетов, 0 зачислений; публичный платёжный шлюз остаётся закрытым.
- **Создание счёта через API с реальным email и действительным пилотным токеном пока не проверено**, поэтому успешный переход к платёжной форме не обещать заранее. Проверить ошибку AnyPay по возвращаемому коду, если появится.
